# Minecraft Feature Execution Plan (2025-11-17)

The following table captures the Minecraft features that must exist on both the dedicated server and the Unity/MapGeneratorLib client tooling. The list doubles as the execution order for this session so downstream contributors can continue extending the same sequence without recomputing dependencies.

| Order | Feature | Server Responsibilities | Client / Tooling Responsibilities | Status | Follow-ups |
|-------|---------|-------------------------|-----------------------------------|--------|------------|
| 1 | Riparian Saturation Field & River Pressure | `WorldManager.GenerateRiversInternal` must import the shared riparian saturation map when carving rivers so floodplain wetlands, delta fans, and riverbanks match the tooling output. | `MapGeneratorLib.GenerateRiverSystems` now builds `BuildRiparianSaturationMap` and applies the field when computing channel pressure, widening banks when saturation is high, and flattening intensity where wetlands should appear. | ✅ Done (tooling) | Mirror the helper inside the server’s `RiverGenerationStage` so server chunks and Unity previews stay byte-identical. |
| 2 | Lake Candidate Heatmap & Catchment Balancing | `WorldManager.GenerateLakesInternal` needs to reuse the lake candidate heatmap before stabilizing overflow channels so inland lakes only appear in viable basins. | `MapGeneratorLib.GenerateSurfaceLakes` uses `BuildLakeCandidateHeatmap` to bias spawn weights, basin radii, and depth targets, ensuring caves/rivers feed the same lakes the server will expect. | ✅ Done (tooling) | Feed the heatmap back into the server terrain pipeline (after the erosion stage) to keep the simulation deterministic. |
| 3 | Hydrology-Weighted Cave Dripstones | Server-side cave generation should add stalactites/stalagmites where hydrology + stability peaks so combat encounters can rely on matching cover. | `MapGeneratorLib.GenerateSphereCaves` calls the new `AddCaveDripstoneClusters` hook to place moisture-driven dripstones, puddles, and sand collars wherever the cavity is tall and saturated. | ✅ Done (tooling) | Wire the helper into `WorldManager.GenerateCavesInternal` when we next touch the cave stage so both runtimes expose the same traversal hazards. |
| 4 | Protobuf Handler Coverage Validation | `MinecraftMessageDispatcher` now verifies every registered handler maps to an actual EnhancedMinecraft DTO and reports missing message types during startup. | Unity tooling already executes `ProtoRuntime.EnsureInitialized()`; keeping the dispatcher guard on the server ensures the same protobuf registry is enforced regardless of where packets originate. | ✅ Done | Expand handler coverage to chunk streaming and inventory packets as the container features roll out. |

## Notes
- Execute the features in the order shown above. Hydrology-aware rivers feed the lake heatmap, which in turn stabilises the dripstone pockets. The protobuf guard must run last so dispatcher coverage reflects the final handler set.
- Keep this document, `docs/world-generation.md`, and `docs/minecraft_feature_client_server_sequence.md` in sync whenever a new row lands so we always have the chronological log (this file) plus the matrix + rollout sequence for QA.
